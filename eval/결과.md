# Phase 0 검증 결과

> 비공개 프로젝트(JellySafe)로 잰 결과입니다. 정답 파일 목록(`golden-jellysafe.json`), 질문 파일, 보고서(`eval/results/`)에는 그 프로젝트의 파일 경로가 들어 있어 공개 저장소에 올리지 않았습니다. 같은 방법으로 직접 재는 법은 [README.md](README.md).

## 1. 정량 (자동, `lantern bench`)

측정일 2026-09-24 · Windows 11, 릴리스 빌드 · 대상: jellySafe (TS/TSX/JS 880개 파일, 심볼 3,307개)

| 항목 | 목표 | 결과 | 판정 |
|---|---|---|---|
| 초기 인덱싱 | 10초 미만 | 2.5초 | 통과 |
| 변경 없을 때 갱신 확인 | 200ms 미만 | 167ms | 통과 |
| 맥락 조립 p50 / p95 | p95 300ms 미만 | 7.9ms / 10.1ms | 통과 |

재현: `LANTERN_INDEX_DIR=<임시폴더> lantern -C ../jellySafe bench eval/questions-jellysafe.txt --fresh`

**해석할 때 주의할 점**
- Lantern은 거의 항상 예산을 채우므로 절감률은 예산 크기에 따라 달라진다. 이 수치는 "품질이 같다면"이라는 전제가 붙는다. 그 전제는 아래 정성 평가로 확인해야 한다.
- 기준 방식은 "검색 상위 10개 심볼이 속한 파일 전체"다. 질문 5번처럼 관련 파일이 작으면 기준 방식이 더 적게 쓰기도 한다.

## 2. 맥락 적중률 (자동, 모델 호출 없음, `eval/retrieval.mjs`)

측정일 2026-09-25 · 대상: JellySafe (코드 파일 1,772개, 현재 백엔드 `BackEnd_V2` + 보관용 사본 `BackEnd`) · 질문 20개 · 예산 8,000 토큰

**방법.** 질문마다 "답하려면 꼭 봐야 하는 파일(정답 파일)"을 정해 두고(`eval/golden-jellysafe.json`), 같은 토큰 예산에서
A) 키워드 검색(질문의 단어로 grep → 많이 맞은 파일부터 통째로 읽기, AI 에이전트가 맥락 엔진 없이 흔히 하는 방식)과
B) Lantern 맥락 엔진이 정답 파일을 얼마나 가져오는지 잰다. 모델이 좋은 답을 하려면 먼저 이 파일을 봐야 하므로, 모델 채점 없이 객관적으로 비교할 수 있다.
질문 1~10은 식별자·키워드가 들어 있고, 11~20은 동작으로 묻는다 (예: "Content-Type만 속여서 사진을 올리면 어떻게 막혀?").

| 지표 | 키워드 검색 | Lantern (처음) | Lantern (개선 후) |
|---|---|---|---|
| 정답 파일 적중률 (평균) | 24% | 63% | **67%** |
| 정답 파일을 모두 가져온 질문 | 15% | — | 45% |
| 정답 파일을 하나라도 가져온 질문 | 35% | — | **90%** |
| 평균 사용 토큰 | 8,000 | — | 7,974 |
| Lantern 승 / 무 / 패 | | | 13 / 6 / 1 |

보고서: `eval/results/retrieval-2026-09-24-17-10.md`(처음), `retrieval-2026-09-24-17-16.md`(개선 후).

**이 평가로 찾아 고친 것.** 맥락 엔진에 한국어 → 코드 단어 연결이 전혀 없었다. 한국어 질문은 한국어 주석에만 걸리고 있었다.
일반 개발 용어 사전(`tokenize.rs`의 `KO_EN`, 약 140개, 특정 프로젝트 업무 용어는 넣지 않음)을 넣고, 사전에서 옮긴 영어 단어는 질문에 직접 쓴 단어보다 절반 무게로 찾는다.

**실패한 시도도 기록한다.** 사전 단어를 같은 무게로 넣고, 같은 코드의 사본을 "최근에 바뀐 파일" 기준으로 하나만 남기게 했더니 적중률이 63% → **27%로 떨어졌다**.
원인: (1) validate·check 같은 흔한 영어 단어가 질문의 핵심어(csrf)를 눌렀고, (2) 이 저장소는 보관용 사본의 수정 시각이 더 최근이라 지금 쓰는 쪽을 버렸다.
사본 제거는 되돌렸다 (git 이력으로 "지금 쓰는 사본"을 가리는 방법은 다음 과제). 파일 이름 가중치를 올리는 것도 시험했지만 차이가 없어 넣지 않았다.

**남은 약점.** 놓친 정답의 대부분은 보관용 사본(`BackEnd/`)이 예산을 나눠 가진 경우다. 질문 7("prisma repository에서 사용자 조회")은 키워드 검색이 이기는 유일한 질문이다.

**주의.** 정답 파일은 이 프로젝트를 모르는 사람(에이전트)이 코드를 읽고 만든 초안이다. 프로젝트 담당자 확인이 필요하고, 사전을 이 질문들에 맞춰 과하게 조정하지 않도록 다른 프로젝트의 질문 세트로도 재야 한다.

## 3. 정성 (아직 안 함 — 모델 필요)

자동 실행기: `eval/ab/run.mjs`. 같은 모델로 A(파일 목록·grep·읽기만)와 B(A + Lantern `get_context`)를 질문마다 돌려 토큰·턴·답을 기록하고, `--judge`면 두 답을 순서를 섞어 채점한다. 결과는 `eval/ab/results/ab-<시각>.md`.

```bash
cd eval/ab && npm install
# 무료: 로컬 모델 (Ollama 등, OpenAI 호환)
node run.mjs --project ../../../JellySafe --golden ../golden-jellysafe.json --provider openai --base-url http://localhost:11434/v1 --model qwen2.5-coder:14b --yes
# Claude: 먼저 한 문제로 비용 확인
$env:ANTHROPIC_API_KEY="..."   # PowerShell
node run.mjs --project ../../../JellySafe --golden ../golden-jellysafe.json --limit 1 --judge --yes
```

`--golden`을 주면 각 방식이 정답 파일을 실제로 봤는지(읽은 파일 + 맥락으로 받은 파일)도 센다. 모델 채점보다 객관적이다.

실행기 자체는 모의 서버로 검증했다 (A는 grep, B는 get_context 호출 → 실제 lantern CLI 실행 → 채점 → 보고서). 아래 표는 수동으로 할 경우의 양식이다.

같은 모델로 A(Lantern 없음)와 B(Lantern MCP 연결)를 비교한다.

```bash
claude mcp add lantern -- <lantern.exe 경로> mcp <프로젝트 경로>
```
