# Phase 1·2 · Lantern IDE

> 상위 문서: 기획서(비공개) 3장, 5장, 8장 · 선행: [Phase0_맥락엔진_설계.md](Phase0_맥락엔진_설계.md)
> 상태: 구현 완료, 실사용 검증 대기 · v0.1 · 2026-09-24

## 1. 구성

```
app/
├─ index.html, src/*.ts        # 화면 (프레임워크 없이 TypeScript + CodeMirror 6 + xterm.js)
└─ src-tauri/src/
   ├─ main.rs        # Tauri 명령 등록
   ├─ state.rs       # 앱 상태, 경로 안전 검사, 월별 사용량 기록
   ├─ config.rs      # 설정 병합: 기본값 ← ~/.lantern/config.toml ← <프로젝트>/.lantern/config.toml
   ├─ agents.rs      # 에이전트 정의 (.lantern/agents/*.md)
   ├─ agent.rs       # 에이전트 루프: 맥락 조립 → 모델 → 도구 → 반복
   ├─ tools.rs       # 도구 10종과 승인 절차
   ├─ llm/           # 모델 라우터: anthropic.rs (Messages API), openai.rs (OpenAI 호환), sse.rs
   ├─ lsp.rs         # 언어 서버 stdio 중계
   ├─ terminal.rs    # PTY 셸
   ├─ hooks.rs       # on_save, on_agent_done 훅
   └─ workspace.rs   # 파일 트리, 파일 목록, 읽기
```

맥락 엔진(`crates/lantern-context`)은 라이브러리로 직접 링크한다. IDE 안에서는 MCP를 거치지 않는다.

## 2. 기능

### Phase 1 · 최소 에디터

| 기능 | 구현 |

| LSP | `[lsp.<언어>]` 설정의 서버를 필요할 때 띄움. 자동완성, 진단, 호버, 정의로 이동(F12, 다른 파일이면 탭을 엶), 참조 찾기, 이름 바꾸기 |

| 실행 인자 | `lantern-app <폴더>`로 바로 열기 |

### 상용화 다듬기 (v0.2)

- 정체성: 남색 기운의 무채색, 남색 = 사용자 동작·포커스, 청록 = 맥락 엔진이 한 일. Pretendard(내장), Cascadia, 육각형 표시. 디자인 기준은 [PRODUCT.md](../PRODUCT.md)와 DESIGN.md.
- 다크·라이트 테마 (시스템 설정 따르기 기본), 편집기 문법 색은 VS Code Dark+/Light+.
- 첫 실행 "시작하기" 탭: 모델 연결(Claude 키 또는 로컬 Ollama·LM Studio 자동 탐지) → 폴더 → 사용법. 1단계는 실제 연결 확인을 통과해야 완료.
- 설정 화면: 모델(추가, 기본 지정, 연결 확인, API 키), 비용 한도, 맥락 예산, 에이전트 권한, 훅, 화면. 저장 위치는 사용자 전체(`~/.lantern/config.toml`) 또는 프로젝트. TOML의 주석과 순서를 보존하고(toml_edit), 잘못된 값이면 저장을 되돌린다.
- API 키는 OS 자격 증명 저장소(Windows 자격 증명 관리자)에 저장. 찾는 순서: 환경변수 → 자격 증명 저장소 → 설정 파일.
- 알림 토스트와 알림 기록(상태 표시줄 종). 채팅 사이드바를 가리지 않고, 변경 승인 대기 중에는 오류가 아닌 알림을 띄우지 않는다.
- 채팅의 "Lantern이 본 코드" 카드: 이번 질문에 붙인 파일·심볼·포함 이유(`'세션', '쿠키' 일치`, `` `login`가 사용 `` 등). 상태 표시줄에 마지막 맥락 예산 사용량(`맥락 46 · 8.0k/8.0k`).
- 좁은 창: 메뉴를 햄버거로 접고, 사이드바 폭을 줄인다. 처음 실행 시 창이 1100px보다 좁으면 채팅 사이드바를 닫고 시작.

### 상용화 기능 (v0.3)

| 영역 | 내용 |
|---|---|
| 폴더 신뢰 · 제한 모드 | 처음 여는 폴더는 신뢰 여부를 묻는다. 신뢰하지 않으면 프로젝트 `.lantern` 설정·에이전트·훅을 무시하고, 에이전트는 읽기 도구만 쓴다 (설정 파일로 모델 주소를 바꿔 키와 코드를 빼돌리는 공격 차단). 상태 표시줄에 "제한 모드", 파일 메뉴에서 신뢰 전환 |
| 비밀 가리기 | 모델에 보내는 맥락, 도구 결과, 로그, 자동 완성 요청에서 API 키·토큰·개인 키·비밀번호 대입을 «가려진 비밀»로 바꾼다. `.env`, `*.pem` 같은 비밀 파일은 에이전트가 읽기 전에 승인을 받는다 |
| 파일 작업 | 탐색기 오른쪽 클릭 메뉴, 새 파일·폴더, 이름 바꾸기(인라인), 휴지통으로 삭제, 탐색기에서 보기. 열린 탭은 경로를 따라간다 |
| 외부 변경 감지 | 파일 감시(300ms 묶음). 저장하지 않은 탭은 건드리지 않고, 트리·소스 제어·`.lantern` 설정을 다시 읽는다 |
| 소스 제어 (Ctrl+Shift+G) | 상태·브랜치·ahead/behind, 스테이징/해제, 변경 취소(새 파일은 휴지통), 커밋(Ctrl+Enter), 저장소 만들기, 파일별 Diff 탭, 활동 표시줄 배지 |
| AI 작업 되돌리기 | 에이전트 실행마다 처음 바꾸기 직전의 원본을 체크포인트로 남기고, 채팅의 "이 작업 되돌리기"로 한 번에 복원 (새로 만든 파일은 휴지통) |
| 파일에서 바꾸기 (Ctrl+Shift+H) | 글자 그대로 바꾸기(대소문자 옵션), 파일별·전체 바꾸기. 저장하지 않은 탭의 파일은 건너뛴다. 바꾼 뒤 토스트의 "되돌리기"로 복원 |
| 단축키 편집 | 파일 > 단축키. 행을 두 번 클릭해 새 키 입력, 끄기, 기본값. 데이터 폴더의 `keybindings.json`(VS Code와 같은 모양)에 저장되고 직접 고쳐도 된다 |
| 로그 · 문제 보고 | 데이터 폴더 `logs/lantern.log`(2MB에서 교체), 패닉 시 충돌 보고서, 다음 실행 때 알림. 도움말 > 문제 보고는 비밀을 가린 보고서를 보여주기만 하고 보내지 않는다 |
| 언어 서버 자동 설치 | 서버가 없으면 설치를 제안. npm 패키지는 Lantern 데이터 폴더 `servers/`에 설치(전역 npm을 건드리지 않음), rust-analyzer는 `rustup component add`. 설치 후 열린 탭에 바로 연결 |
| 영어 화면 | 설정 > 화면 > 언어. 원문(한국어)을 키로 한 사전(`app/src/locales/en.json`)을 DOM 관찰자로 적용하므로 화면 코드를 감쌀 필요가 없다. 편집기·터미널·채팅 본문은 번역하지 않는다. 빠진 번역은 `python scripts/i18n_check.py`로 찾는다 |
| 업데이트 | 하루 한 번 조용히 확인, 도움말 > 업데이트 확인. 서명 검증 후 설치하고 다시 시작 ([배포 가이드](배포_가이드.md)) |
| 인라인 자동 완성 | 설정 > 모델 > 인라인 자동 완성에서 모델을 고르면 켜진다(기본 끔). 타이핑을 멈추면 커서 앞뒤를 보내 제안을 흐리게 표시, Tab 수락·Esc 무시. 비용 한도를 넘으면 멈춘다 |

### 작업과 지도 (v0.4, 차별화)

설계 배경과 경쟁 도구 비교: [차별화_작업과_지도.md](차별화_작업과_지도.md)

| 기능 | 내용 |
|---|---|
| 작업 중심 구조 | 활동 표시줄 맨 위가 "작업"(Ctrl+Alt+T)과 "프로젝트 기억". 작업마다 대화·보낸 맥락·발자취·되돌리기가 묶이고, 여러 작업을 오가도 각자의 대화가 유지된다. 승인을 기다리는 작업 수는 활동 표시줄 배지로 |
| 편집기 / 지도 전환 | 제목 표시줄 가운데 전환, Ctrl+Alt+M. 프로젝트를 열면 지도부터 보이고, 파일을 열면 편집기로 돌아간다 |
| 코드 지식그래프 | 파일 150개 이하는 파일 단위, 넘으면 폴더(모듈) 단위로 시작해 두 번 눌러 파일 → 심볼로 내려간다. 간선: 참조·호출(화살표), 함께 바뀜(점선, git 이력), 기억 연결(점점선). 모듈별 색, 검색(이름·경로), 끌기·확대, 이름표 겹침 방지, 정보 카드(부르는 곳/부르는 것, 연결된 기억, 코드 열기·주변 보기·영향 보기) |
| 에이전트 발자취 | 지금 작업에서 AI에 보낸 맥락(청록 채움), 읽은 파일(청록 점선), 수정(남색 채움, 심볼은 실제로 바뀐 것만)을 지도에 겹친다. 에이전트가 방금 본 곳에 번지는 고리. 작업 머리와 목록에 개수 |
| 변경 영향 반경 | 파일 수정 승인 카드에서 바뀌는 줄의 심볼 → 직접·간접 호출자, 영향 파일·모듈, 함께 바뀌던 파일, 테스트 유무, 위험도(낮음/보통/높음). "지도에서 보기"로 빨강(바뀌는 곳)·주황(직접)·주황 점선(간접)·초록(테스트) 지도 |
| 프로젝트 기억 지도 | `.lantern/memory/*.md`의 목록 줄 하나가 기억 하나. 기억 보기에서 읽기·고치기·지우기·더하기, 기억이 언급한 심볼·파일을 칩으로. 지도의 "기억" 겹쳐 보기와 기억 지도에서 규칙이 걸린 코드를 본다 |

| 작업 저장 | 앱 데이터 폴더에 작업 기록·모델 대화·되돌리기 원본 저장. 다시 켜면 대화·발자취·되돌리기까지 복원, 실행 중에 닫힌 작업은 "중단됨" |
| 작업 격리 | 작업 시작 전 "격리"를 고르면 git worktree에서 실행 → 변경 보기 / 프로젝트에 적용(충돌이면 아무것도 바꾸지 않음) / 버리기 |
| 겹침 경고 | 격리하지 않은 작업끼리 같은 파일을 고치면 작업 목록에 "겹침", 되돌릴 때 그 뒤 바뀐 파일이 있으면 한 번 더 확인 |
| 언어 서버 확인 | 켜진 언어 서버로 바뀌는 심볼의 참조를 다시 세어 영향 반경에 반영 |

백엔드는 `crates/lantern-context/src/graph.rs`(전체 지도, 폴더 펼치기, 주변, 영향 반경, 기억 연결, 찾기), `app/src-tauri/src/tasks.rs`(저장), `worktree.rs`(격리)이고, 화면은 `app/src/map.ts`(d3-force 배치 + 캔버스), `chat.ts`(작업), `memory.ts`.
