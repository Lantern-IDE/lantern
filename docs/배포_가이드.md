# 배포 가이드

## 0. GitHub에서 세 운영체제 릴리스 만들기 (권장)

버전을 올리고(아래 "버전은 세 곳을") 태그를 올리면 `.github/workflows/release.yml`이 Windows(.exe), macOS(.dmg, 유니버설), Linux(AppImage, .deb) 설치 파일과 업데이트 서명, `latest.json`을 만들어 **초안 릴리스**에 올립니다. 초안에서 릴리스 노트를 채우고 게시하세요.

```bash
git tag v0.1.0 && git push origin v0.1.0
```

저장소 비밀값 `TAURI_SIGNING_PRIVATE_KEY`에 업데이트 서명 키 내용이 들어 있어야 합니다 (`gh secret set TAURI_SIGNING_PRIVATE_KEY < ~/.tauri/lantern-updater.key`).

### macOS 서명과 공증
지금 .dmg는 임시 서명(`signingIdentity: "-"`)만 되어 있습니다. 공증 전이라 사용자가 처음 열 때 막히므로 설치 안내에 다음을 적어 둡니다: 앱을 **응용 프로그램**으로 옮긴 뒤 `xattr -cr /Applications/Lantern.app` 실행, 또는 **시스템 설정 → 개인정보 보호 및 보안 → 그래도 열기**. ★ 정식 배포에는 Apple Developer Program(연 99달러)의 Developer ID 인증서와 공증이 필요합니다. tauri-action에 `APPLE_CERTIFICATE`, `APPLE_ID`, `APPLE_PASSWORD`, `APPLE_TEAM_ID` 환경변수를 주면 서명과 공증을 함께 합니다.

아래 1~3절은 Windows 설치 파일을 로컬에서 직접 만드는 방법입니다.

설치 파일을 만들고, 자동 업데이트를 켜고, 서명하는 방법. **표시(★)한 단계는 사업자·도메인·인증서가 필요해 직접 해야 합니다.**

## 1. 설치 파일 만들기

```bash
cd app
npx tauri build          # target/release/bundle/nsis/Lantern_<버전>_x64-setup.exe
```

설치 파일 설정은 `app/src-tauri/tauri.conf.json`의 `bundle`:
- 사용자 폴더에 설치 (`installMode: currentUser`) → 관리자 권한 필요 없음
- 설치 화면 언어: 한국어·영어 (선택 가능)
- 게시자(`publisher`), 저작권 문구는 지금 "Lantern"으로 되어 있습니다. ★ 상호가 정해지면 바꾸세요.

## 2. 자동 업데이트

### 서명 키 (이미 만들어 둠)
업데이트 파일은 서명을 검증한 뒤에만 설치됩니다. 키는 저장소 밖에 있습니다.

| 파일 | 용도 |
|---|---|
| `C:\Users\<사용자>\.tauri\lantern-updater.key` | **비밀 키.** 릴리스 빌드에서 업데이트 파일에 서명. 절대 저장소에 넣지 마세요. 잃어버리면 기존 사용자에게 업데이트를 보낼 수 없습니다 → 안전한 곳에 백업 |
| `...\lantern-updater.key.pub` | 공개 키. `tauri.conf.json`의 `plugins.updater.pubkey`에 이미 들어 있음 |

지금 키에는 비밀번호가 없습니다. 비밀번호를 걸려면 `npx tauri signer generate -w <경로> -p <비밀번호>`로 새로 만들고 `pubkey`를 바꾸세요 (첫 배포 전이라면 부담 없이 바꿔도 됩니다).

### 업데이트 서버 주소
`tauri.conf.json` → `plugins.updater.endpoints`는 GitHub Releases의 최신 릴리스를 가리킵니다:

```json
"endpoints": ["https://github.com/Lantern-IDE/lantern/releases/latest/download/latest.json"]
```

`releases/latest`는 **정식(pre-release가 아닌) 릴리스**만 가리킵니다. 베타를 pre-release로 올리면 업데이트 확인에 잡히지 않고, 확인에 실패해도 로그에만 남습니다 (메뉴에서 직접 확인하면 실패 안내가 뜹니다).

### 릴리스 빌드

```powershell
$env:TAURI_SIGNING_PRIVATE_KEY = "$HOME\.tauri\lantern-updater.key"   # 경로 또는 키 내용 (Tauri v2는 _PATH 변수를 읽지 않음)
$env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = ""        # 비밀번호를 걸었다면 입력
cd app
npx tauri build --config src-tauri/tauri.release.conf.json
```

`tauri.release.conf.json`은 업데이트 파일(`*.nsis.zip`, `*.sig`)도 함께 만듭니다. 일반 빌드에서 빼 둔 이유는 서명 키 없이도 빌드가 되게 하려는 것입니다.

그다음 `latest.json`을 만들어 설치 파일과 함께 올립니다. `node scripts/latest_json.mjs`가 빌드 결과와 `.sig`를 읽어 만들어 줍니다 (아래는 그 형식):

```json
{
  "version": "0.2.0",
  "notes": "변경 내용 요약",
  "pub_date": "2026-10-01T00:00:00Z",
  "platforms": {
    "windows-x86_64": {
      "signature": "<.sig 파일 내용>",
      "url": "https://github.com/Lantern-IDE/lantern/releases/download/v0.2.0/Lantern_0.2.0_x64-setup.exe"
    }
  }
}
```

Tauri v2는 NSIS 설치 파일(`*-setup.exe`) 자체에 서명(`*-setup.exe.sig`)을 만듭니다. 이미 만든 설치 파일에는 `npx tauri signer sign -f <키 경로> -p "" <설치 파일>`로 서명만 따로 할 수 있습니다.

GitHub에 올리기:

```bash
gh release create v0.2.0 --repo Lantern-IDE/lantern --title "Lantern 0.2.0" --notes-file <변경 내용.md> \
  target/release/bundle/nsis/Lantern_0.2.0_x64-setup.exe \
  target/release/bundle/nsis/Lantern_0.2.0_x64-setup.exe.sig \
  target/release/bundle/nsis/latest.json
```

베타는 `--prerelease`를 붙입니다.

버전은 세 곳을 같이 올리세요: `app/src-tauri/tauri.conf.json`, `app/src-tauri/Cargo.toml`, `app/package.json`.

## 3. ★ 코드 서명 (Windows SmartScreen)

서명하지 않은 설치 파일은 "Windows에서 PC를 보호했습니다" 경고가 뜨고, 다운로드 수가 적을 때 특히 심합니다. 상용 배포 전에 필요합니다.

- 인증서: OV 또는 EV 코드 서명 인증서 (사업자 등록 필요). 요즘은 대부분 하드웨어 토큰·클라우드 HSM으로 발급됩니다. Azure Trusted Signing도 선택지입니다.
- 설정: `tauri.conf.json`의 `bundle.windows`에 `certificateThumbprint`(로컬 인증서) 또는 `signCommand`(클라우드 서명 도구)를 넣으면 `tauri build`가 exe와 설치 파일에 서명합니다.

```json
"windows": {
  "signCommand": "trusted-signing-cli -e https://<지역>.codesigning.azure.net -a <계정> -c <프로필> %1"
}
```

업데이트 서명(2절)과 코드 서명은 별개입니다. 둘 다 필요합니다.
